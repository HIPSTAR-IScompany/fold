# Fold protocols and implementations

Fold introduces Infoton Engineering broadly and research on Fold7G, Trion Bond, Fold8G, and related protocols. A generation label does not mechanically identify a conventional network layer: inspect the subject, rules, and implementation.

| Source of authority | Responsibility |
|---|---|
| ZeroRoomLab Manifest | General FAM theory and Fold8G World, Authority, and claim boundaries |
| saitoomituru/fold-nic | Parsers, resolvers, adapters, key boundaries, receipts, and tests |
| SphereOS Atlantis | PLI and CLI, Execution Envelope, MAGI, and Sphere-DOS upstream contracts |
| This site | Research explanations, indexes, and cross-references |

The current Fold8G proposal addresses Identity, Authority, Capability, Provenance, and Transport between Worlds. A Fold Identity is distinct from a DNS domain, GNS zone key, GitHub account, or transport endpoint.

## Check implementation state

The adopted fold-nic boundary document separates its control plane and offline checks from unimplemented parser, resolver, GNS adapter, and P2P delivery surfaces. Consult implementation commits and tests for later changes.

The public Web remains an entrance for people, search, and review. A future namespace design does not require waiting to publish current research documentation.
